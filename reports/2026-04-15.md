### 1. Claude Code Routines：AI 编程助手有了"工作流引擎"

💡 一句话说清楚：Anthropic 给 Claude Code 加了一个叫 Routines 的功能，让你可以把常用的编程操作流程固化下来，一键执行。

🔍 为什么重要：这是 AI 编程工具从"你问一句我答一句"到"你定义一个流程我自动跑完"的关键跳跃。598 分的 HN 头条、GitHub Trending 上 4 个与 Claude Code 相关的项目（andrej-karpathy-skills 9263⭐、claude-mem 2997⭐、claude-code-best-practice 2583⭐），加上 Yannic Kilcher 专门出视频分析 Claude Code 的工作原理——这说明整个开发者社区都在认真研究怎么用好这个工具。

🧩 技术拆解：想象你用前端构建工具的场景。以前的 AI 编程助手像是你在终端里手动敲命令——每次都要重新输入。Claude Code Routines 更像是你写了一个 `npm script` 或 `Makefile`：把"创建组件→写测试→跑 lint→提交 PR"这种多步骤流程定义好，然后一键执行。而 GitHub 上爆火的那些 "skills" 和 "best-practice" 仓库，本质上就是社区在共享彼此的 `npm scripts`——"这是我调教出来的最佳工作流配置，拿去用"。

🛠 实际落地：如果你还没用 Claude Code，现在是入场的好时机。从简单的开始：把你日常重复的开发任务（比如"根据设计稿创建 React 组件并写 Storybook"）写成一个 Routine。先看看 GitHub 上 andrej-karpathy-skills 的 CLAUDE.md 怎么写的——它本质上就是一份"给 AI 的行为规范"，类似于你项目里的 .eslintrc，只不过约束的是 AI 的编码行为。

### 2. Chrome Skills：Google 把"AI 提示词"变成了浏览器里的小工具

💡 一句话说清楚：Google 在 Chrome 里加了一个功能叫 Skills，让你把常用的 AI prompt 保存成一键工具，还能分享给别人。

🔍 为什么重要：这意味着 AI 能力正在被"控件化"。以前用 AI 要打开 ChatGPT 输入一大段话，现在变成浏览器里的一个按钮。对于前端工程师来说，这预示着一种新的交互范式——未来你可能需要设计和开发这类"AI 微工具"的容器和分发系统。

🧩 技术拆解：把 Chrome Skills 想象成浏览器的 Bookmarklet 2.0。Bookmarklet 是把一段 JavaScript 存成书签一键执行；Chrome Skills 是把一段 AI prompt 存成按钮一键执行。再进一步类比：这就像 VS Code 的 Snippets 系统——你定义模板，留几个变量占位符，然后快速调用。只不过执行引擎从代码解释器变成了 LLM。

🛠 实际落地：打开 Chrome 体验一下 Skills 功能。试着把你工作中常用的 prompt 做成 Skill——比如"把这段英文技术文档翻译成中文并提取关键术语"、"分析这个页面的可访问性问题"。更重要的是，思考一下：如果你要为团队或产品构建类似的"prompt 即工具"体验，技术栈会是什么样的？

### 3. AI Agent 安全亮红灯：40 种攻击模式被编目

💡 一句话说清楚：当 AI Agent 开始替你执行任务（发邮件、写代码、调 API），安全问题就炸了——有人整理出 40 种针对 AI Agent 的攻击方式，Nvidia 发布了 Agent 安全框架，多个安全检测工具同时涌现。

🔍 为什么重要：今天的数据里至少有 5 个相关信号：MCP Attack Atlas 编目了 40 种攻击模式、Nvidia 发布 OpenShell 安全框架、ArmorIQ 做 Agent 行为合规检测、OpenAI 发布网络安全专用模型 GPT-5.4-Cyber、void-box 用微型虚拟机隔离 Agent。这不是巧合——当 Agent 从"聊天"变成"执行"，安全就从"可选"变成"必须"。

🧩 技术拆解：用前端安全来类比。你知道 XSS 吧？用户输入恶意内容，浏览器当代码执行了。AI Agent 面临的核心问题类似——"Prompt Injection"就是 AI 时代的 XSS：攻击者在看似正常的文档里藏一段指令，Agent 读到后把它当成命令执行。MCP（Model Context Protocol）是 Agent 调用外部工具的协议，类似于浏览器里的 Fetch API——MCP Attack Atlas 列出的 40 种攻击，就像是有人整理了一份"Fetch API 可以被滥用的 40 种方式"。而 void-box 用微型虚拟机跑 Agent，思路和你用 iframe sandbox 隔离不可信内容一样——不信任就隔离。

🛠 实际落地：如果你的产品开始集成 AI Agent 功能（比如让 AI 帮用户自动填表单、调后端 API），现在就要把安全设计纳入考量。去看看 MCP Attack Atlas（sunglasses.dev/mcp-attack-atlas）上的攻击模式列表，了解攻击面在哪里。核心原则和前端安全一样：永远不要信任来自外部的输入，Agent 的每个动作都需要权限边界。

### 4. 本地跑大模型：手机、消费级硬件正在变成 AI 节点

💡 一句话说清楚：有人把小米 12 Pro 刷成 AI 推理服务器 24/7 运行，有人用消费级显卡跑 1220 亿参数模型，llama.cpp 新增"热门专家缓存"技术让 MoE 模型推理速度提升 27%。

🔍 为什么重要：AI 正在从"只能在云端"走向"到处都能跑"。Reddit 上那个用小米手机当 AI 服务器的帖子拿了 925 分——不是因为这很实用，而是因为它代表了一种可能性：AI 推理不需要 A100，你的旧手机就行。加上 MiniMax M2.7 的开源许可证讨论、DGX Spark 到货测评、llama.cpp 的性能优化——整个生态在为"人人都能跑模型"铺路。

🧩 技术拆解：这就像前端的 SSR vs CSR 之争在 AI 领域重演。Cloud AI 是 SSR——所有计算在服务器端完成，客户端只收结果。Local AI 是 CSR——模型和推理都在本地跑。而 llama.cpp 新增的"热门专家缓存"（Hot Expert Cache）特别有意思：MoE（Mixture of Experts）模型有很多"专家"子网络，但每次推理只激活几个。这个优化把常用的专家预加载到 GPU 显存里，就像浏览器把热门资源放进 Service Worker Cache——不是全部缓存，而是智能缓存最常用的那些。

🛠 实际落地：如果你想体验本地 AI，最低门槛的方式：安装 Ollama（ollama.com），下载 Gemma 4 或 Qwen 3.5 的小参数版本，在你的开发机上跑起来。然后用它的 API 替代部分 ChatGPT 调用——比如代码审查、commit message 生成。这既能让你理解 AI 推理的基本概念，又有实际生产力价值。

### 5. LLM 没你想的那么强：一个标点符号就能让它崩溃

💡 一句话说清楚：一篇新论文发现，只要禁止 LLM 使用某个标点符号或常用词，它的回答质量就会暴跌 14%-48%，变得前言不搭后语。

🔍 为什么重要：这篇论文叫"One Token Away from Collapse"——名字就很说明问题。我们天天用的 GPT、Claude，看起来很智能，但实际上它们的"智能"建立在非常脆弱的统计模式上。同时今天还有 KillBench 发现所有前沿 LLM 在"谁应该活下去"的道德判断上都有偏见，HBR 文章说 LLM 给的"战略建议"大多是"潮流废话"。这三个信号加在一起的信息是：别盲信 AI 的输出。

🧩 技术拆解：类比前端：这就像你的 CSS 框架依赖某个 reset stylesheet，一旦删掉某条 reset 规则，整个布局就崩了。LLM 的"知识"不是像数据库一样结构化存储的，而是通过 token 之间的统计关联模式编码的——禁掉一个高频 token，就像抽掉了这个关联网络里的一个关键节点，后续的 token 预测全部偏移。这也解释了为什么"提示词工程"如此重要又如此不稳定——你在操纵的是一个统计系统，而不是一个逻辑系统。

🛠 实际落地：如果你在产品里集成了 AI 功能，记住这个教训：永远要对 AI 输出做后处理和校验。就像你不会把用户输入直接渲染成 HTML 一样，也不要把 AI 输出直接展示给用户。加一层验证、加 fallback 方案、给用户"这个回答有用吗？"的反馈机制。
